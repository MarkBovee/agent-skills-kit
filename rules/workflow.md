# ASK Workflow Mandate

- Load the most specific matching workflow skill with `skill(name: '...')` before substantial work; router matches are advisory and never replace the skill body.
- For large, multi-issue, exhaustive, compatibility-sensitive, or release-sensitive work, load `intake`, create a plan artifact, classify risk, define must/should/could scope, and complete plan-check before execution.
- When a brief asks for maximum results or says not to optimize for the smallest change, record every evidence-backed candidate as must, should, could, or explicitly out of scope. A deferred item needs a reason and a revisit trigger.
- Delegate independent research, validation, review, and audit tracks by default. Keep one coordinator responsible for reconciled conclusions and final integration.
- Never declare merge, release, or tag readiness from self-review alone. Release-sensitive work needs independent validation, review, audit, and release-gate evidence.
- Preserve project independence: use repository-specific names only as evidence inside a task, never as generic workflow behavior.
